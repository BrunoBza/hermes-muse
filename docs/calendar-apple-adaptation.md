# Apple PIM observation adaptation

The 30-day view previously excluded Apple events because the strict normalized contract required source timezone, original all-day dates and original recurrence identity that Apple PIM 3.18.0 does not expose. An interval view can display current observed events without offering synchronization or cancellation-history guarantees. The strict contract remains unchanged for fully described sources; Apple raw receipts opt into a separately labelled observation mode.

`hermes_muse/apple_calendar.py` is pure stdlib transformation. It accepts actual Apple calendar/event page items, an explicit connector-host device timezone, and the ordinary immutable window/page receipts. It validates device-local strings against UTC, retains original payload and provenance, and distinguishes observed expanded instances using native ID and returned interval. It neither invents RECURRENCE-ID nor expands masters. All-day device display dates are separate from original source dates; unknown availability is explicitly annotated. Evidence-supported Muse preparation annotations enter the existing candidate flow without creating notices.

Apple source coverage always remains partial with capability explanations, including after all resources were read or an empty query. Successfully read resources are retained independently of semantic completeness. Invalid events preserve valid page neighbors. No automatic state, source-check, calendar or scheduling writes are introduced. The existing official Apple runner, permissions and service remain authoritative.

Validation under the actual Hermes launcher/bootstrap: 107 unit tests passed (11 existing calendar tests and 8 new Apple tests), native integration passed with raw Apple receipts through the registered calendar_view action, and all 14 official plugin validator checks passed without warnings. Live read acceptance uses isolated Hermes state, explicit opt-in paths to the existing authorized runner and only a 30-day calendar query. Six calendars returned four all-day events, including one with recurrence rules; all four were displayed, all six reads retained, Apple partial and overall complete=false. No personal event titles, bodies or IDs appear in this report or saved acceptance summaries. Google was not re-read in this Apple-focused acceptance; mixed strict/Apple assembly is exercised synthetically through the native action.

The acceptance harness was corrected before passing: bootstrap concatenation originally produced a double semicolon and the outer runner initially failed to propagate child return codes; run_path needed an explicit tests import path; dateRange echoes use whole seconds and must be checked at their actual formatting precision while query arguments remain unchanged. These harness failures do not establish a Muse implementation failure or a validation pass. The corrected runner checks every child return code and exits nonzero for any failure.

No deployment, restart, live plugin reload, calendar mutation or connector patch was performed. Installed feed.md remains preserved. Exact commit/tree, source archives and sanitized execution logs are recorded in the external Apple-adaptation acceptance report.
