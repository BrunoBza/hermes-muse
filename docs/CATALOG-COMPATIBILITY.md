# Compatibility decisions in 0.1.27

This version retains the six recurring jobs, their schedules, notice policy, rolling 30-day/natural-month calendar, source coverage/watermarks and follow-through lifecycle. Local goal registration creates no Cron; it remains available for recovery of genuinely accepted but unregistered work under the original signal/24-hour rules.

Model-created watches in native Cron context now require the active profile's `cron.allow_agent_scheduling: true`. A recorded user signal does not override that operator setting. Fixed installation jobs and ordinary goal state/verification are separate. Watch prompt and stop_condition must each be nonempty strings of at most 4,000 characters; errors do not truncate scope. This limit does not shorten shipped prompts or the assembled wrapper. Store complete accepted scope in the managed goal, use verifiable references and recheck cancellation; a reference grants no authority and bypasses no scheduling guard. An omitted watch schedule defaults to every 30 minutes. Explicit shorter schedules, one-off reminders and existing user job settings retain native semantics: the proposed absolute 30-minute floor is **not implemented**.

Conversation context is a preview: newest 24 eligible messages per session, up to 1,000 characters of each and 24,000 text characters shared across sessions. Complete native content remains available via `conversation_read` in 12,000-character pages under the exact revision. One latest-revision range/hash record is kept per tracked session (replaced on change, no automatic TTL); no conversation body is copied. Only previews returned to the caller and explicit pages count as served; internal freshness checks do not mark unseen text. partial coverage prevents notice review/finalization. A final page alone cannot certify skipped pages; changed messages invalidate old coverage. These are conversation-preview budgets, not a maximum on total work, full operation audit, signal batches, research results or all tool/context metadata. Existing signal/operation/source processing cursors are not advanced by conversation reads. Original candidate/reply evidence continues to use precise native identity/hash matching independently of previews.

Cron delegation uses public `ctx.dispatch_tool` when readonly configuration establishes route parity (no delegation route/parameter/fallback override). Actual native Cron declares stateless delivery and the public tool falls back to joined execution. Config changes observed across dispatch return explicit uncertainty and the native result, never a retry. Ordinary chat keeps native delegation routing. **A private routing exception remains** for configured or unknown conflicting delegation routes, preserving the previously accepted Muse parent-model/connection contract without changing global settings. Results identify the route branch. This does not resolve the request to eliminate every private call; a public scoped inherit-parent policy is needed to preserve that behavior alongside an independent global delegation pin. It does not bypass native pause, permissions, depth, iteration or concurrency limits. No plugin option is added and no global config is changed.

Research/audit allocate at most three workers and respect a lower effective configured/environment limit. Unknown budgets allocate one. All questions and pending audit slots remain; fewer workers is not less coverage. Model-supplied ineffective toolsets are rejected before dispatch. Delegates are **instructed** to remain read-only under inherited host tools/permissions, not confined by a host-wide sandbox. File, terminal, browser and enterprise MCP toolsets may include writes. Muse rejects child business-state write actions, but allowed context/status/evidence paths can perform bookkeeping. Do not claim absolute zero writes or a hard read-only tool allowlist.

## Retention disclosure

The profile-local signal inbox stores the first 8,000 Python characters of each private/local user input, a truncation flag, source turn/session identity and timestamp. Associated session routes, when present, include platform, chat/user/thread/message/scope identities and session routing keys. The newest 500 signals are retained even after processing. Older signals are eligible for removal only after **both** memory-upkeep and nightly-review cursors cover them, with cleanup triggered by a subsequent input. Unprocessed backlog can exceed 500; there is no fixed maximum retention time. Cutting this backlog would lose unprocessed intent, so this version documents rather than discards it.

Native full conversation/tool history has separate Hermes retention and may be pruned/unavailable; removing an inbox row does not delete native history, memory, goals, Feed or backups. Followup candidates/receipts/reply hashes are metadata; unresolved items are retained and eligible settled metadata is lazily cleaned under its documented lifecycle. Research records can contain returned native result payloads, including joined report text. Audit page receipts contain references with seven-day expiry; findings, goal/Feed/notes and existing memory are separate persistent records/files governed by explicit lifecycle/forgetting. There is no second full native transcript or telemetry, but this is not a claim that only metadata or no sensitive result text is stored anywhere.

## Validation scope

Use synthetic native histories and tasks, temporary homes, actual plugin registration/core dispatch/Cron isolation, complete unit/native smoke and official validator. Provider/transport fixtures do not establish live model quality or delivery. Catalog admission remains a maintainer decision. New code is not automatically deployed to an existing installation by publication.
